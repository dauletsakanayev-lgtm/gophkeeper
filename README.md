# GophKeeper

![CI](https://github.com/dauletsakanayev-lgtm/gophkeeper/actions/workflows/ci.yml/badge.svg)

Дипломный проект курса «Go-разработчик» от Yandex Practicum.

Клиент-серверная система для безопасного хранения паролей, произвольных
текстовых/бинарных данных и данных банковских карт. Данные шифруются
на стороне клиента (end-to-end), сервер видит только шифрованные blob'ы.

## Компоненты

- **`cmd/server`** — HTTP-сервер, хранит пользователей и зашифрованные секреты
  в PostgreSQL.
- **`cmd/client`** — кросс-платформенный CLI-клиент (Windows / Linux / macOS)
  для регистрации, аутентификации и работы с секретами.

## Поддерживаемые типы секретов

| Тип       | Описание                                          |
|-----------|---------------------------------------------------|
| `login`   | пара логин / пароль                               |
| `text`    | произвольный текст                                |
| `binary`  | произвольные бинарные данные                      |
| `card`    | номер карты, срок действия, имя владельца, CVV    |

Для любого секрета можно хранить произвольную текстовую метаинформацию
(принадлежность к сайту, список одноразовых кодов и прочее).

## Быстрый старт

```bash
# Поднять PostgreSQL для локальной разработки
make db-up

# Собрать сервер и клиент
make build

# Запустить сервер
./bin/gophkeeper-server -a :8080

# Запустить клиент
./bin/gophkeeper --help
```

## Разработка

- Требуемая версия Go: 1.26+
- Форматирование: `gofmt`, `goimports`
- Линт: `go vet ./...`
- Тесты: `make test` (покрытие ≥ 70%)

Полный список make-целей: `make help`.

## Безопасность

- Транспорт: TLS (сертификат задаётся флагами сервера).
- Аутентификация: JWT с коротким TTL.
- Шифрование секретов: **клиент** → Argon2id из master password → AES-256-GCM.
  Master password никогда не покидает клиент и не пишется на диск.
- Хранение на сервере: только шифрованные blob'ы, сервер не имеет ключа
  и не может расшифровать содержимое даже с root-доступом к БД.
